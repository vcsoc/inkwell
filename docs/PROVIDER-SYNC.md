# Provider writes

**Microsoft:** New or reauthorized Outlook/Microsoft 365 accounts request delegated `Mail.ReadWrite` and `Calendars.ReadWrite` in addition to the existing read/send scopes. Existing read-only grants are never silently upgraded: use **Settings → Mail accounts → Grant mail/calendar access**, sign in to the *same* mailbox, and review Microsoft's consent screen. Reauthorization replaces only that account's encrypted token; it does not replace downloaded messages, drafts, or local calendar entries. Organizations may require admin consent. A different identity is rejected.

Once a single Microsoft calendar account is authorized, **Local changes only** defaults off. In Settings → Mail accounts, turning it on keeps *future* changes on this device. Provider operations already queued before the switch still complete. It cannot be turned off without the write grant. The tooltip explains this behavior; status and failures appear in the shared footer and settings. The provider write queue is durable in the same SQLite transaction as the local change, with four workers, per-item ordering, exponential backoff, bounded retries, an error indicator, and a manual **Retry failed changes** action. Offline, pending changes are **not yet provider-synced**: do not mistake the local view for confirmed remote state.

Supported Graph writes: read/unread; stars/flags (both map to Outlook's single flag); inbox/archive/Trash and connected remote-mail-folder moves; permanent deletion; and create/update/delete for calendar events, including bounded daily, weekly, monthly and yearly recurring events. Immutable Microsoft message IDs and per-resource ordering let a timed-out move be reconciled before retry. Calendar creates carry a stable Graph transaction ID to avoid duplicate retries. A 404 from the *delete action* does not prove a message was deleted. Existing local events are not automatically uploaded; editing one after enabling provider writes adopts it. Local-only metadata (tags, custom local folders, local sent copies, unsent local drafts, old unedited events, remote-content permissions) remains on-device. Moving an eligible Microsoft message to a local-only folder is rejected while provider writes are enabled, instead of pretending the server copy moved. Microsoft Bookings/ICS acceptance creates an event, **not** an Outlook invitation RSVP.

**IMAP/SMTP:** these accounts currently have no provider-write or calendar connection. Their mail and calendar changes remain local. A CalDAV provider connection (and IMAP write/move support) would be required to make them provider-synced; the Microsoft toggle does not grant these capabilities. Provider sync cannot be guaranteed while offline or if a grant expires; failed operations stay visible until corrected or retried. The application does not force-close unsaved drafts to apply any of these changes.
